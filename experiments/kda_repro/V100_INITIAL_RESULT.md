# V100 KDA 通用流程：首次可复现实验结果

> 审核更正：下列数值仅为早期 smoke 测试观察，晋级结论暂停。旧验证仅检查梯度有限，
> 并未验证梯度数值正确；单次 launch 的计时也可能受到主机提交开销影响。
> 已补充随机上游梯度与参考梯度比较，须在 V100 重跑后才能认定候选可用。

**运行时间：** 2026-09-18；**设备：** Tesla V100-PCIE-32GB（sm70，32GB）；
**软件：** Python 3.10.12、PyTorch 2.5.1+cu121、Triton 3.1.0。

本结果复现的是 KDA 的通用闭环：先定义任务契约，再完成基线、正确性验证、计时、
候选实现与晋级记录。它不是 B200 FlashInfer 竞赛结果，也不能与官方排行榜比较。

## 任务与验证

任务为 FP16 `Residual Add + RMSNorm` 前向：同时返回残差和归一化输出。验证覆盖
`[64, 768]`、`[64, 1024]`、`[64, 4096]` 三个形状；输出与独立 FP32 归约参考比较，
并检查从标量损失得到的输入和权重梯度均存在且有限。

候选采用一行一个 Triton program，将残差相加、FP32 RMS 归约、缩放和两个输出写回
融合为一次 kernel launch；反向使用显式公式以保持该任务的训练语义。

## 结果

| Shape | PyTorch 基线中位数 | Triton 候选中位数 | 加速比 |
| --- | ---: | ---: | ---: |
| 64×768 | 0.139648 ms | 0.110928 ms | 1.2589× |
| 64×1024 | 0.138400 ms | 0.091472 ms | 1.5130× |
| 64×4096 | 0.140016 ms | 0.091504 ms | 1.5302× |

旧运行通过前向比较与梯度有限性检查，曾记录为 `promoted`；该结论现撤回，等待严格
梯度验证及重复计时。远端独立工作区 `/home/huids25/kda-repro/workspaces/v100-residual-rmsnorm`
保存了 `runs/` 原始日志、`benchmark.csv` 与 `candidates.jsonl`。

## 限制与下一步

- 当前镜像不含 `ncu`，尚无 Nsight Compute 的瓶颈证据；补齐工具后应为基线和候选各采集
  一份 profile。
- 此候选只验证了模板内的 FP16 连续输入和三个代表形状；需要扩展形状、非连续布局与
  Megatron 真实调用路径后，才能作为框架级优化结论。
- B200 专用 FlashInfer 复现仍需 B200 与官方依赖组合。V100 的价值是先完成可审计的
  KDA 工作流和候选迭代。
