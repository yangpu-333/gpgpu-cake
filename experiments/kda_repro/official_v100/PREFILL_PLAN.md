# GDN Prefill 候选计划

在 Decode 的完整正确性检查通过后扩展多步递推。独立 program 持有一个序列、head 和一组 V 行的 FP32 state，依时间顺序更新，最后写回状态。BF16 位转换沿用 Decode；不跨时间并行改变递推关系。

官方 100 组真实输入全部与定义内原始 reference 对比，逐元素 atol=rtol=0.01，并记录误差。候选为 ROWS=4/8/16。没有通过的候选不得计时或晋级。不修改输入、不放宽容差，追加空序列和 state=None 分支。

Prefill 的 Python 循环参考仅作为正确性标准；与其计时比较不能解释为相对官方优化库的加速。本轮首先检查长序列数值稳定性并记录候选自身时延。
