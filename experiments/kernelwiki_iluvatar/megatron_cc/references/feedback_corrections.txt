Corrections to archived CLI feedback/rationales (raw replies remain unchanged):
1. feedback_prompt_0002.txt mistakenly quoted the early 5-launch smoke forward+backward ratios as if they represented the full screening matrix. Full screening was roughly 0.91-1.10x forward+backward for FP32 residual (0001, v2), not 9-12x. Promotion always uses the full fixed wall-clock training samples, never the smoke figures.
2. CUDA event timing can include host launch gaps on the stream; it is not a pure kernel-instruction execution measure and does not categorically exclude host costs.
3. cProfile included a cold compile (~0.345s) in the ~0.395s forward launcher total. Cold compilation was already excluded from the training benchmark. The host-dispatch explanation was a hypothesis, not a verified exclusive cause of regression.
4. v1/v2 GPU float64 numerical comparisons were superseded by v3 CPU copies after an unequal-pair probe proved a false-zero path. Tolerances, baseline, input distributions and timing code were unchanged. Both original candidates passed the v3 CPU operator matrix (224 finite cases and 16 separately labelled native-invalid compatibility cases) and model correctness.
5. v3 screening training ratios: 0001=0.899387 (native11.489975ms, candidate12.775334ms); 0002=1.003156 (native11.250569ms, candidate11.215175ms). These single-process screens do not establish stable promotion.
